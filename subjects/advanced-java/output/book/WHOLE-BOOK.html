Introducing Swing [5]

🎬 Animation: lessons/u1-introducing-swing.html

Definition

Swing is a Java GUI toolkit (package javax.swing) used to build windows, buttons, text boxes and other graphical parts. It is built on top of AWT and is written fully in Java.

Features of Swing

  • Lightweight: components are drawn by Java, not by the operating system.
  • Pluggable look and feel: the style can be changed at run time.
  • MVC based: data (model) is separate from display (view).
  • Platform independent: looks the same on all OS.
  • Rich components: JTable, JTree, JTabbedPane, etc. (names start with J).

Displaying Information in a Component [5]

🎬 Animation: lessons/u1-displaying-information.html

Definition

To display information in a component, we make a class that extends JPanel (or JComponent) and override paintComponent(Graphics g). Java calls this method automatically whenever the component needs to be drawn.

Key points

  • paintComponent(Graphics g) is called by Java, not by us.
  • Call super.paintComponent(g) first to clear the background.
  • The Graphics object is the pen: drawString(), drawLine(), drawRect().
  • Coordinates are in pixels; (0,0) is the top-left corner.
  • To redraw, call repaint().

Event Handling Basics [5]

🎬 Animation: lessons/u1-event-handling-basics.html

Definition

Event handling is the way a Java program reacts to user actions like clicks and key presses. Java uses the Delegation Event Model: a source sends an event object to registered listeners.

Parts of the Delegation Event Model

  • Event Source: component that generates the event (JButton).
  • Event Object: holds information about the event (ActionEvent).
  • Event Listener: interface whose method runs when the event occurs (ActionListener).

Figure

[Event Source] --event object--> [Registered Listener] --> handler method runs

Steps to handle an event

  1. Implement the listener interface.
  2. Register it: source.addXxxListener(listener).
  3. Override its method (e.g. actionPerformed).
🔔Event Source
👆User acts
📩Event object is made
🧑‍🍳Sent to the Listener
Topic trick (model)Some Elephants Listen = Source → Event → Listener (Delegation Event Model)
Points trick (3 coding steps)Ice Reaches Ocean = Implement interface · Register (addXxxListener) · Override method

KeyEvent [5]

🎬 Animation: lessons/u1-keyevent.html

Definition

KeyEvent is a class in java.awt.event that represents a keyboard action when the user presses, types, or releases a key.

Key Points

  • Belongs to java.awt.event and works with KeyListener or KeyAdapter.

Event Listener [3+2]

🎬 Animation: lessons/u1-event-listener.html

Definition

An Event Listener is a Java interface (in java.awt.event or javax.swing.event) that listens for an event on a GUI component and runs code to respond to it.

Role of Event Listener

  • Connects the Event Source (like a button) to the response code.
  • Provides methods that run automatically when a specific event occurs.
  • Keeps UI design separate from event logic so code stays neat and easy to update.

Adapter Classes [2.5]

🎬 Animation: lessons/u1-adapter-classes.html

Definition

An Adapter class gives blank default bodies for all methods of a listener interface that has multiple methods.

Key points

  • Examples: MouseAdapter, KeyAdapter, WindowAdapter, FocusAdapter, MouseMotionAdapter.
  • Avoids writing empty methods you do not need when implementing a listener interface directly.
  • You override only the method you care about.

What Is a Java Bean? [2.5]

🎬 Animation: lessons/u3-what-is-java-bean.html

Definition

A JavaBean is a reusable Java class (software component) that follows simple rules so tools and programs can use it easily.

Rules of a JavaBean

  • Has a public no-argument constructor.
  • Fields (properties) are private.
  • Properties are accessed with public getter/setter methods (getX(), setX(), isX() for boolean).
  • Implements Serializable so its state can be saved.
  • Can fire and listen to events.

Example

    private String name;
    private int age;
    public Student() { }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }
}

The Life Cycle of a Servlet [2.5 / 5]

🎬 Animation: lessons/u4-servlet-life-cycle.html

Definition

The servlet life cycle is the set of steps a servlet goes through from loading to removal, managed by the web server/container.

Stages

  • Loading and instantiation: container loads the class and creates one object.
  • init(ServletConfig): runs once when the servlet starts (e.g. opening a DB connection).
  • service(ServletRequest, ServletResponse): runs for every request and calls doGet() or doPost().
  • destroy(): runs once before shutting down to clean up resources.

What is RMI? [2.5]

🎬 Animation: lessons/u5-what-is-rmi.html

Definition

RMI (Remote Method Invocation) lets a Java program in one JVM call a method on an object running in another JVM over a network.

Key points

  • Package java.rmi.
  • Works only between Java programs (Java-to-Java).
  • Uses stub (client) and skeleton (server) to hide network details.
  • Objects are passed using serialization.
  • RMI Registry is used to find remote objects.
  • Used for distributed applications (banking, chat, remote calculators).

Remote Method Calls [5]

🎬 Animation: lessons/u5-remote-method-calls.html

Definition

A remote method call is a call from a client to a method of an object in another JVM. The stub and the server side do all the network work.

Steps

  • Client calls a method on the stub.
  • Stub marshals (packs) the method ID and parameters.
  • Data is sent over the network (TCP/IP).
  • Server side (skeleton) unmarshals the parameters.
  • The real method runs on the remote object.
  • Return value is marshalled back; the stub unmarshals and returns it to the client.

Stubs and Parameter Marshalling [5]

🎬 Animation: lessons/u5-stubs-marshalling.html

Definition

A stub is a client-side proxy for a remote object. Parameter marshalling is packing method parameters into a byte stream to send them over the network (unmarshalling is unpacking them).

Key points

  • Stub implements the same remote interface as the real object.
  • Stub: starts connection, marshals parameters, sends, waits, unmarshals result.
  • Uses Java serialization for objects.
  • Primitive types are sent by value.
  • Non-remote objects must be Serializable and are sent as copies.
  • Remote objects are sent as stubs (by reference).
  • Since Java 5 stubs are created automatically (no rmic needed).

The RMI Programming Model (Architecture) [5 / 10]

🎬 Animation: lessons/u5-rmi-architecture.html

Definition

RMI (Remote Method Invocation) lets a Java program in one JVM call a method on an object running in another JVM over a network. Its architecture has layers on both client and server.

Key parts

  • Client & Server: client calls remote methods; server holds and runs the remote object.
  • Stub (client side): local stand-in; packs arguments and unpacks return values or errors.
  • Skeleton (server side): receives calls, unpacks arguments, runs the method, sends back the result. (Old; removed after Java 1.2 but still asked.)
  • Remote Reference Layer: handles remote object references and how connections are made.
  • Transport Layer: sends/receives raw data (TCP/IP).
  • RMI Registry: phonebook where the server registers the object name and the client finds it.

Simple Client/Server Application using RMI [10 program]

🎬 Animation: lessons/u5-rmi-client-server-app.html

Definition

A simple RMI application has a remote interface, an implementation, a server that registers the object, and a client that looks it up and calls it.

Steps

  • Create the remote interface (extends Remote).
  • Implement it (extends UnicastRemoteObject).
  • Server: create the registry and rebind the object.
  • Client: look up the object and call methods.
  • Compile all, run server, then run client.

Example

import java.rmi.*;
import java.rmi.server.*;
import java.rmi.registry.*;

interface Adder extends Remote {
    int add(int a, int b) throws RemoteException;
}

class AdderImpl extends UnicastRemoteObject implements Adder {
    AdderImpl() throws RemoteException { super(); }
    public int add(int a, int b) throws RemoteException { return a + b; }
}

class Server {
    public static void main(String[] args) throws Exception {
        Registry reg = LocateRegistry.createRegistry(1099);
        reg.rebind("adder", new AdderImpl());
        System.out.println("Server ready");
    }
}

class Client {
    public static void main(String[] args) throws Exception {
        Registry reg = LocateRegistry.getRegistry("localhost", 1099);
        Adder a = (Adder) reg.lookup("adder");
        System.out.println("Sum = " + a.add(5, 7));
    }
}
