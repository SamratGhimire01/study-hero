What is RMI? [2.5]

🎬 Animation: lessons/u5-what-is-rmi.html

Definition

RMI (Remote Method Invocation) lets a Java program in one JVM call a method on an object running in another JVM over a network.

Key points

  • Package java.rmi.
  • Works only between Java programs (Java-to-Java).
  • Uses stub (client) and skeleton (server) to hide network details.
  • Objects are passed using serialization.
  • RMI Registry is used to find remote objects.
  • Used for distributed applications (banking, chat, remote calculators).

Remote Method Calls [5]

🎬 Animation: lessons/u5-remote-method-calls.html

Definition

A remote method call is a call from a client to a method of an object in another JVM. The stub and the server side do all the network work.

Steps

  • Client calls a method on the stub.
  • Stub marshals (packs) the method ID and parameters.
  • Data is sent over the network (TCP/IP).
  • Server side (skeleton) unmarshals the parameters.
  • The real method runs on the remote object.
  • Return value is marshalled back; the stub unmarshals and returns it to the client.

Client → Stub (marshal) → Network → Skeleton (unmarshal) → Remote Object

Stubs and Parameter Marshalling [5]

🎬 Animation: lessons/u5-stubs-marshalling.html

Definition

A stub is a client-side proxy for a remote object. Parameter marshalling is packing method parameters into a byte stream to send them over the network (unmarshalling is unpacking them).

Key points

  • Stub implements the same remote interface as the real object.
  • Stub: starts connection, marshals parameters, sends, waits, unmarshals result.
  • Uses Java serialization for objects.
  • Primitive types are sent by value.
  • Non-remote objects must be Serializable and are sent as copies.
  • Remote objects are sent as stubs (by reference).
  • Since Java 5 stubs are created automatically (no rmic needed).
📞Stub = local stand-in
🧳Marshalling = packing the suitcase
🧳Bytes travel to the server
🛎️Unmarshalling = unpacking
Topic trickStub = Stand-in, Marshal = Pack
Points trick (passing rules)Primitives Copy, Objects Copy, Remotes Reference = int/double by value · Serializable objects by copy · Remote objects by stub reference

The RMI Programming Model (Architecture) [5 / 10]

🎬 Animation: lessons/u5-rmi-architecture.html

Definition

RMI (Remote Method Invocation) lets a Java program in one JVM call a method on an object running in another JVM over a network. Its architecture has layers on both client and server.

Key parts

  • Client & Server: client calls remote methods; server holds and runs the remote object.
  • Stub (client side): local stand-in; packs arguments and unpacks return values or errors.
  • Skeleton (server side): receives calls, unpacks arguments, runs the method, sends back the result. (Old; removed after Java 1.2 but still asked.)
  • Remote Reference Layer: handles remote object references and how connections are made.
  • Transport Layer: sends/receives raw data (TCP/IP).
  • RMI Registry: phonebook where the server registers the object name and the client finds it.

| Remote Object | <- | Skeleton | <- | Remote Ref.  | <- | Transport |
+---------------+    +----------+    | Layer (RRL)  |    |  Layer    |

Interfaces and Implementations [5]

🎬 Animation: lessons/u5-interfaces-implementations.html

Definition

In RMI, the remote interface declares the methods a client may call remotely, and the implementation class on the server provides the real code.

Key points

  • Remote interface extends java.rmi.Remote.
  • Every remote method throws RemoteException.
  • Implementation extends UnicastRemoteObject (or uses UnicastRemoteObject.exportObject()).
  • Implementation constructor throws RemoteException.
  • Client works only with the interface type (via the stub).

The RMI Registry [2.5]

🎬 Animation: lessons/u5-rmi-registry.html

Definition

The RMI Registry is a simple naming service (like a phonebook) where a server registers remote objects by name, and clients look them up. Default port is 1099.

Methods (Registry / Naming)

  • bind(name, obj): add a name (error if it exists).
  • rebind(name, obj): add or replace.
  • unbind(name): remove.
  • lookup(name): get the stub.
  • list(): all names.

Start the registry

rmiregistry 1099 (command) or LocateRegistry.createRegistry(1099) (code).

Remote Object Activation [2.5]

🎬 Animation: lessons/u5-remote-object-activation.html

Definition

Remote object activation lets a remote object be started on demand (only when a client calls it) instead of running all the time.

Key points

  • Uses package java.rmi.activation.
  • Object extends Activatable.
  • The activation daemon rmid starts the object when needed.
  • Registered with an ActivationDesc (descriptor).
  • Saves memory and server resources; objects survive server restarts.
  • Note: deprecated in Java 15 and removed in Java 17, but it is in the syllabus.

⚙️Method runs

Simple Client/Server Application using RMI [10 program]

🎬 Animation: lessons/u5-rmi-client-server-app.html

Definition

A simple RMI application has a remote interface, an implementation, a server that registers the object, and a client that looks it up and calls it.

Steps

  • Create the remote interface (extends Remote).
  • Implement it (extends UnicastRemoteObject).
  • Server: create the registry and rebind the object.
  • Client: look up the object and call methods.
  • Compile all, run server, then run client.

Example

import java.rmi.*;
import java.rmi.server.*;
import java.rmi.registry.*;

interface Adder extends Remote {
    int add(int a, int b) throws RemoteException;
}

class AdderImpl extends UnicastRemoteObject implements Adder {
    AdderImpl() throws RemoteException { super(); }
    public int add(int a, int b) throws RemoteException { return a + b; }
}

class Server {
    public static void main(String[] args) throws Exception {
        Registry reg = LocateRegistry.createRegistry(1099);
        reg.rebind("adder", new AdderImpl());
        System.out.println("Server ready");
    }
}

class Client {
    public static void main(String[] args) throws Exception {
        Registry reg = LocateRegistry.getRegistry("localhost", 1099);
        Adder a = (Adder) reg.lookup("adder");
        System.out.println("Sum = " + a.add(5, 7));
    }
}
📜1. Interface Adder
🏗️2. AdderImpl
📒3. Server starts registry + rebind
🔎4. Client: getRegistry + lookup

Comparing RMI with CORBA [2.5 / 5]

🎬 Animation: lessons/u5-rmi-vs-corba.html

Definition

CORBA (Common Object Request Broker Architecture) is a standard that lets programs written in different languages on different machines talk to each other over a network.

CORBA key points

  • Uses IDL (Interface Definition Language) so any language can understand the interface.
  • Uses an ORB (Object Request Broker) to pass requests and replies between client and object.
  • Works across different languages and operating systems (protocol IIOP).
PointRMICORBA
LanguageJava onlyAny language (C++, Java, Python…)
InterfaceJava interfaceIDL
ProtocolJRMP (or IIOP)IIOP
ComplexitySimpleMore complex
Objects passedBy value (serialization) or referenceMostly by reference
Garbage collectionDistributed GCNo distributed GC
